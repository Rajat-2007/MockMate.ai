# Runbook

How to set up, run, migrate, test and troubleshoot MockMate AI.

## 1. Prerequisites

| Tool | Version | Check |
| --- | --- | --- |
| Node.js | 22 LTS or newer | `node -v` |
| npm | 10+ | `npm -v` |
| Python | 3.11+ (3.12 recommended) | `python --version` |
| PostgreSQL | 16 (or Docker) | `psql --version` |
| Redis | 7 (or Docker) | `redis-cli ping` |
| Docker Desktop | current, WSL 2 backend on Windows | `docker compose version` |
| Ollama | current (Phase 4 onward) | `ollama -v` |

## 2. First-time setup

```bash
git clone <repo-url> mockmate-ai
cd mockmate-ai

cp .env.example .env                       # compose + scripts read this
cp backend/.env.example backend/.env       # API reads this
cp frontend/.env.example frontend/.env.local
```

Minimum backend values:

```ini
DATABASE_URL=postgresql+psycopg://mockmate:mockmate@localhost:5432/mockmate
REDIS_URL=redis://localhost:6379/0
SECRET_KEY=<32+ random characters>
BACKEND_CORS_ORIGINS=http://localhost:3000
```

## 3. Start the stack

### 3.1 Docker (single command)

```bash
docker compose up --build          # db, redis, backend, frontend
docker compose logs -f backend
docker compose down                # keeps volumes
docker compose down -v             # destructive: drops database data
```

### 3.2 Local processes

```powershell
docker compose up -d db redis
```

Backend:

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
alembic upgrade head
uvicorn app.main:app --reload --port 8000
```

Frontend:

```powershell
cd frontend
npm install
npm run dev
```

### 3.3 Ports

| Service | Port |
| --- | --- |
| Frontend | 3000 |
| API | 8000 |
| API docs | 8000/docs |
| PostgreSQL | 5432 |
| Redis | 6379 |
| Ollama | 11434 |

## 4. First-run verification

1. `curl http://localhost:8000/api/v1/health` → `{"status":"ok", ...}`.
2. `curl http://localhost:8000/api/v1/health/live` → liveness only.
3. Open `http://localhost:8000/docs`.
4. Open `http://localhost:3000` → hero, categories, pricing, FAQ render.
5. `http://localhost:3000/robots.txt` and `/sitemap.xml` return entries.
6. Resize to 390px: mobile menu opens, sections reflow to one column.
7. `docker compose exec backend alembic current` → `20261110_0001 (head)`.

If `DATABASE_URL` is empty, step 1 still returns `200` with
`checks.database.configured = false`. That is the intended
"not configured" state, not a failure.

## 5. Database and migrations

```bash
cd backend
alembic current                                  # applied revision
alembic upgrade head                             # apply everything
alembic downgrade -1                             # roll back one
alembic revision --autogenerate -m "add profiles"   # review the output before committing
alembic upgrade head --sql                       # render SQL offline (no DB needed)
```

Backup and restore:

```bash
pg_dump -U mockmate -h localhost mockmate > backup.sql
psql -U mockmate -h localhost -d mockmate < backup.sql
```

Rules:

- Never hard-code the database URL in `alembic.ini`; it comes from `DATABASE_URL`.
- Always read autogenerated migrations before committing (enum and server
  default changes need manual care).
- Run `alembic upgrade head` as a deploy step; the container entrypoint already
  does this for compose.

## 7. Adding a backend module

1. Model in `app/models/`, imported from `app/models/__init__.py`.
2. Migration in `alembic/versions/` (`alembic revision --autogenerate`).
3. Pydantic schema in `app/schemas/`.
4. Logic in `app/services/`.
5. Router in `app/api/v1/endpoints/`, registered in `app/api/v1/__init__.py`.
6. Test in `backend/tests/`.

## 8. Adding a frontend page

1. Create the route under `src/app/(marketing)/<route>/page.tsx` and export
   `metadata` with a unique title, description and canonical.
2. Compose it from `components/marketing/*` and `components/ui/*`.
3. Add copy to `src/lib/marketing-data.ts` rather than inline, so it is typed
   and testable.
4. Add the path to `src/app/sitemap.ts` and to `src/config/site.ts` navigation.
5. `npm run typecheck && npm run build`.

## 9. Troubleshooting

| Symptom | Cause and fix |
| --- | --- |
| `CORS` error in the browser | `BACKEND_CORS_ORIGINS` must list the exact frontend origin including port |
| Login works in curl, not in the browser | cookies need `credentials: "include"` on the client and `allow_credentials=True` on CORS |
| `relation "users" does not exist` | run `alembic upgrade head` |
| `password authentication failed` | mismatch between `POSTGRES_*` in `.env` and `DATABASE_URL` |
| `RuntimeError: DATABASE_URL is not set` from Alembic | export it or create `backend/.env` |
| Port already in use | `netstat -ano \| findstr :3000` then stop that PID |
| `Next.js encountered the unstable value new Date()` | with Cache Components, do not read the clock during prerender; use a static constant |
| Vitest "ESM syntax in a file loaded as CommonJS" | keep the config as `vitest.config.mts` (already done) |
| Playwright browsers missing | `npx playwright install --with-deps` |
| Ollama model missing (Phase 4) | `ollama pull llama3.2:3b` and match `OLLAMA_MODEL`; for Docker, verify `OLLAMA_BASE_URL` uses `host.docker.internal` |
| Image `standalone` output missing in Docker | `output: "standalone"` must stay in `next.config.ts` |

## 10. Production checklist

- `ENVIRONMENT=production`, `DEBUG=false`.
- `SECRET_KEY` set to 32+ random characters (the app refuses to start otherwise).
- `BACKEND_CORS_ORIGINS` lists real origins only.
- `DATABASE_URL` points at the managed Postgres in the chosen region.
- Migrations applied before the new container is promoted.
- `NEXT_PUBLIC_*` values are the public HTTPS/WS URLs, set at image build time.
- HTTPS terminated in front of both services; secure cookies enabled.
- Backups scheduled and a restore tested.
